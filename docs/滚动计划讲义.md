# 滚动计划讲义：预测变了，怎么办？

## 1. 三条铁律

1. **过去不可改写**：已经实际发生的供水、入流、弃水是前缀事实，滚动重算时这些时段
   的决策变量被固定为实际值（账目行标 `已执行`），优化器只在"当前时刻之后"做决策。
2. **承诺要付代价**：上次确认时向用户承诺的后续供水量 C 进入新计划：
   - 通知期内（示例规则默认 2 个时段）：`D = C` 是**硬等式**，来不及通知就不能变（行标 `承诺锁定`）；
   - 通知期外：`D + u ≥ C`，欠诺量 u ≥ 0，按合同单价（默认 10 × 公开权重）计入
     **改变代价**，在汇总中与供水量**分开列示**，不混为一笔；
   - 物理上实在做不到时才欠诺，且欠诺本身是"无法兑现的承诺"，不是节水成绩。
3. **从真实当前库容重算**：实测库容与账面不符时，历史账目不动，差额在重算起点做
   一次性**账面调整**（reconciliation），未来 LP 从实测值起步。

## 2. 一次滚动重算的数据流

```
已确认计划 v1（与当时预测版本绑定，含未来逐户承诺 C）
        │  执行 m 个时段：记录实际入流/供水/弃水/实测库容
        ▼
新预测 v2（可能骤降）+ 可能的曲线修订
        │
        ▼
前缀(固定为实际) │ 未来段 LP：硬边界+生态+承诺(D+u≥C)+公开权重
        │
        ▼
新计划 v2草案 + 承诺改变代价 + 归因表 + 多情景区间
        │  确认前再次核对：有没有新到的实际流量？（后端用确认条数给出告警）
        ▼
确认 v2（与新版本号绑定，成为下一轮的承诺来源；旧版本保留不删）
```

## 3. "计划为什么变了"——归因表怎么读

系统用同一未来视界上的三组反事实 LP 把调整量拆开（单位 m³）：

| 分量 | 含义 | 教学演示 |
|---|---|---|
| 预测改变 | 起点、曲线相同，仅换预测造成的供水差 | 来水倍数调到 0.25×：几乎全部变化落在这一列 |
| 执行偏差(起点) | 旧预测在"当前真实起点"相对原始起点的差 + 前缀实际−计划供水 + 实测−账面库容 | 实际取水 +25%、实测库容 −150 万m³：这一列非零，预测列为 0 |
| 曲线修订 | 新预测、同起点，仅换库容曲线造成的差 | 曲线蓄水量 +8%：当前水位不变、库容重估，这一列非零 |
| 未解释残差 | 三者之和与总变化的差（承诺刚性、约束拐点会留下小残差，理论应很小） | — |

**关键判据**：同一次重算里，预测列与执行列不应互相冒充——预测骤降时前缀供水若严格按计划，
执行归因应为 0；执行超用而预测未修订时，预测归因应为 0。测试 `test_rolling.py` 对此做了断言。

## 4. 不同来水情景下的缺口区间与"假概率"

一次可附带偏丰/本次/偏枯多个情景。各情景使用**同一份已确认承诺矩阵和同一份合同规则**
（通知期硬固定、欠诺单价相同），只改变未来来水序列——合同不能随情景放松，否则区间不可比。
每个情景给出：

- 逐户总缺口、逐时段缺口序列；
- 逐户总欠诺量、逐时段欠诺序列、承诺改变代价；
- 期末蓄水。

注意区分：**缺口** = 需求没满足；**欠诺** = 承诺没兑现（欠诺量计入改变代价）。
丰水情景可以供得比承诺多（承诺是下限 D+u≥C），但任何情景不能低于承诺，
通知期内则必须恰好等于承诺。

**没有给出概率的情景，系统只报区间，绝不输出期望值/分位数/"风险概率"**——
那会把无知伪装成精确。给了概率也只是原样保留并展示，不替代正式风险分析。

## 4b. 确认前的持续检查（不依赖当前 active 行）

实际流量会持久化（`actual_observations`，按 step_index 去重覆盖）。确认时计算
**水位线 = max(已持久化观测去重条数, 历次确认实际条数的最大值)**：

- 提交条数 < 水位线：返回 **409 拦截、不写入确认**（例：3 条已确认后提交 2 条拦截，
  再次提交 2 条**仍然拦截**——前一次被拦截不会降低水位线）；
- 拦截后可带 `force=true` 强制确认，确认行标记 `forced` 并保留警告文本；
- 计划依据的 `based_on_version` 若已不是最新确认版本，同样 409（预测/承诺可能已再修订）。

历史确认行全部保留（active 仅一条），因此检查不会因为 active 行被新版本替换而失效。

## 5. 找不到可行计划时

与单次模式相同，未来段 LP 无可行解时给出逐时段诊断，冲突类型新增：

- `commitment`：通知期承诺本身（连击穿死库容都无法兑现）；
- `flood` / `drought`：物理洪峰超容 / 生态与死库容冲突。

紧急豁免（emergency）允许击穿最低保证比例（硬承诺仍守），欠诺代价照计，
用于讨论"极端情况下先救哪头"，不是常规选项。

## 6. 免责

合同规则（通知期、欠诺倍数）是**教学示例参数**，不是任何真实合同文本；
系统不连接闸门、不获取实时监测，滚动计划输出不替代现实调度与应急决策。

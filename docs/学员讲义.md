# 学员讲义：逐时段读懂这盆水

## 1. 每个时段只有一笔账

```
        入流 I
          │
   ┌──────▼──────┐     蒸发 E（净水深 × 水面面积）
   │   水库蓄水   │────▶ 取水 D_生活、D_工业、D_农业 …
   │  V_t → V_{t+1}│────▶ 弃水 S（超过最高库容/溢洪道下泄）
   └─────────────┘
```

平衡式（系统每一行账目都满足，残差可查，量级 < 0.01 m³）：

```
V_t + I_t = E_t + D_life,t + D_industry,t + D_agriculture,t + S_t + V_{t+1}
```

读图顺序建议：

1. **库容/水位图**：蓝面积是蓄水量（左轴，万m³），黄线是水位（右轴，m）——
   水位不是输入的，是用蓄水量查库容曲线换算出来的；
2. **进出水堆叠图**：蓝色"入流"一列的总高度，应等于棕色蒸发 + 各色取水 + 灰色弃水
   再加上库容的增减（库容减少时相当于在动用"存款"）；
3. **取水/缺口图**：每种用户一根柱，实色是拿到的水，红色是没拿到的缺口；
4. **明细表**：点任何一张图，表中对应时段高亮，可逐笔核对上面三式。

## 2. 三类容易混淆的输入

| 情况 | 输入长什么样 | 系统行为 |
|---|---|---|
| 真实零来水 | `{"value": 0, "unit": "万m3"}` | 按 0 参与计算，可能报干旱冲突 |
| 缺测 | `{"value": null, ...}` 或整个字段不给 | **拒绝计算（422）并点名缺测时段**；需显式选 linear/mean/zero 插补，插补值在图表里打"插补"标 |
| 单位不同 | `m³/s`、`l/s`、`h`、`mm`、`亩` | 先统一换成内部单位（m³、m、s）再算账，量纲不一致（如把流量直接当体积）直接报错 |

## 3. 硬条件 vs 权重偏好

- **硬条件**（红线，破了就是"不可行"）：死库容、最高库容、最低生态流量、最低保证比例；
- **权重**（偏好，可以谈判）：生活 3 > 工业 2 > 农业 1 只是示例。
  水够时权重不影响结果；水紧时，LP 把每一立方水给边际收益（权重）最高的用途。

## 4. 当系统说"不可行"

这不表示算错，而是**在给定硬条件下物理上做不到**。冲突框会指出：

- `洪峰超容 flood`：即使弃水到溢洪道上限，平衡库容仍高于最高库容，缺口多少 m³；
- `干旱/生态冲突 drought`：要保最低生态流量就会击穿死库容，差多少 m³；
- `期末目标冲突 target`：指定的期末蓄水量达不到。

讨论题：这时该调整哪个**前提**（预报来水？溢洪道能力？生态流量标准？需求侧压减？），
而不是指望优化器"变出水来"。
